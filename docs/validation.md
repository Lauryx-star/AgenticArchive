# Prototype validation — 2026-10-05

## Environment

- Development host: macOS, Apple Silicon (`darwin/arm64`), Go 1.27.1.
- Container: Debian Bookworm, `linux/arm64`, Docker Desktop.
- The Synology DS218+ (`linux/amd64`) has not been tested yet.
- Existing Apple Command Line Tools were used explicitly for local CGO compilation;
  the default compiler selection required an unaccepted Xcode license.

## Passed checks

- Go unit tests locally and inside the Docker build, plus local race-detector tests.
- `go vet`.
- Incremental import, update, deletion and restart persistence.
- Missing source directory preserves the existing search index.
- Full fingerprint verification detects changes with preserved size/timestamp.
- Failed extraction is recorded and can be retried.
- Literal words, quoted phrases, case-insensitive search, grouped hits, paging,
  modification-date filters and sorting.
- Symlinks outside the archive are not indexed or served as PDFs.
- Docker Compose configuration validation.
- Browser search and mobile layout at a 390-pixel viewport, including light/dark
  theme switching. No horizontal overflow was observed.

## Real PDF/OCR smoke test

Synthetic fixtures generated by `scripts/create-fixtures.py`:

- `text.pdf`: one page with an embedded text layer; search finds `Haftpflicht`.
- `scan.pdf`: one image-only page; OCR finds `Hausrat`, with a page-1 source.
- `broken.pdf`: deliberately invalid; marked as an error without stopping import.

The container reports 2 ready documents and 1 failed document. After replacing
the container with the same persistent volume, both ready PDFs remain searchable
and are reported as unchanged. The broken file is retried and remains an error.
The page-text API confirms `ocr: true` for the image-only PDF, and the PDF endpoint
returns HTTP 200. Phrase search with one result per page returns the correct second
document and a total of two matching documents.

## Memory observation

The container was started with a 512 MiB memory limit, no extra swap and one CPU.
After the initial import, cgroup `memory.peak` reported **81,788,928 bytes
(78 MiB)**. `memory.events` reported no OOM events or OOM kills.

This includes one simple OCR page and one text page on ARM64. It is not a benchmark
of a 5 GiB archive, difficult phone photographs, high-resolution input images or
the DS218+. Image decoding can still exceed the budget for pathological PDFs.

## Remaining validation

- A larger archive with searches running during import.

- Interrupted processing, mount identity across scans and production access control.

## Search excerpt highlighting (2026-10-05)

FTS snippet markers are converted to structured `snippet_parts` containing plain
text and a match flag. The original plain `snippet` field remains available.
The UI creates text nodes and `<mark>` elements without interpreting PDF text
as HTML. Tests cover multiple words, quoted phrases, case/diacritic normalization,
literal HTML-like document text, and path-only hits without unrelated highlights.

Go tests and Docker build tests passed. Browser checks used synthetic documents:
separate Haftpflicht/Nachweis highlights in mobile dark mode and a contiguous
"Haftpflicht Versicherung" highlight in desktop light mode. The updated real
instance retains 494 ready documents; the known Nießbrauchsrecht query returns
12 documents, all with highlighted spans.
